title: lok8s v0.14.1
---

This release fixes the version that the bash tree of
[v0.14.0](https://github.com/kernpilot/lok8s/releases/tag/v0.14.0) reports.
The code is the v0.14.0 code; read its notes for the changes.

## Fixes

- **The bash tree reports its own version.** v0.14.0 was tagged before its
  version references were updated. Its `lo` binary reports 0.14.0
  (`lo version`, the inventory, the `lo toolchain install` header). But the
  bash tree inside it, and the one in the source archive, carries
  `.lok8s/VERSION` 0.13.0. So a tree from `lo assets eject bash`, and a
  `lo version` or a ClusterInventory that runs on the bash implementation,
  report 0.13.0. In v0.14.1 both VERSION files read 0.14.1.
- **The release workflow checks the tag.** Before it builds anything, it
  stops when the tag does not equal both VERSION files
  (`hack/check-release-version.sh`).

## Upgrade

- Pin `lo`, the `kustomize-secret` plugin and the `.lok8s` env ref to
  `v0.14.1`, and run `b update`.
- A project with its own bash tree in `.lok8s/` (`lo assets eject bash`)
  runs `lo assets update bash`, which writes the new `.lok8s/VERSION`. Until
  then, `lo assets diff bash` lists `VERSION` as `lo updated`.
- Nothing reads `.lok8s/VERSION` to decide what to do: `lo version`, the
  inventory and `lo status` only print it. A project that stays on v0.14.0
  works the same; only those printouts say 0.13.0.
