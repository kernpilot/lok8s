One fix, no new command and no change to the piped output of the parity cases.

## Fixed

- Both kubehz agents run on a control-plane-only cluster. The live
  agent's Deployment and the heartbeat CronJob tolerate the
  control-plane taint (`node-role.kubernetes.io/control-plane` and the
  legacy `master` key, `NoSchedule`). Before, on a cluster with one
  server and no worker, or on any cluster whose workers join after
  `lo kubehz deploy`, both pods stayed Pending on the taint: the deploy
  reported "the live agent was accepted but never became Ready", the
  CronJob never ran, and the cluster reported nothing to the platform.
  With workers present the live agent prefers one of them (#228; the
  Deployment is the vendored copy of kubehz-agent's `deploy/base`, which
  carries the same change).

## Changed

- The deploy's Ready-timeout message and the CLI reference name an
  untolerated node taint beside an unpullable image as the usual cause
  of a Pending agent; the kubehz guide says both agents run on a
  control-plane-only cluster.

## Upgrade

Nothing to do. An existing cluster gets the tolerations at its next
`lo kubehz deploy`.
