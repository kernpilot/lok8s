---
title: lok8s v0.15.0
---

This release keeps more credentials out of logs, the process list and git. In
a shared Hetzner project, lo changes only its own parts. It also adds
`lo secrets remove-key`, `lo build --keys-only`, a read-only switch for the
secrets store, and new checks in `lo doctor`. It ships the changes merged
since [v0.14.1](https://github.com/kernpilot/lok8s/releases/tag/v0.14.1).

**Some commands now stop where an older lo went on.** Read
[Changes in behaviour](https://lok8s.io/releases/v0.15.0#changes-in-behaviour)
and [Upgrade](https://lok8s.io/releases/v0.15.0#upgrade) first if you run the
Hetzner provider, the kubehz agent or the `rook-ceph-csi-kms` addon, or if
your project has copies of lo files in `.lok8s/`.

## Security

- **Hetzner Cloud: lo changes only its own parts** (#357). The provider found
  servers, networks, load balancers and other parts by name. In a shared
  Hetzner project that could be a part of another person or of another
  cluster. Each part that lo creates now carries an owner mark (the label
  `lok8s.dev/owner`), and provision, rebuild and destroy act only on a part
  with the mark of this cluster. `lo recover` also refuses a `cluster_name`
  that another domain has (#393), also when it comes in through a YAML merge
  key (#397).
- **`lo destroy` of a remote Lo cluster** stops when the provider fails
  (#357). Before, it went on and removed a cluster with the same name from the
  local docker.
- **The claim ticket of a cluster stays out of logs** (#459, #465). Any
  signed-in kubehz user who has the ticket can claim the cluster. lo prints it
  only on a terminal outside a CI run, or with `--print-token`. The
  `spinup.yml` and `provision.yml` workflows of v0.14.1 wrote it into the job
  log, and `spinup.yml` also into the job summary. If others can read them, claim each cluster
  that is not claimed yet, then delete the workflow runs. A new register stops
  the old ticket only when it sends the current bind secret, and a CI runner
  does not keep that secret. See
  [the guide](https://lok8s.io/guide/deployment#claiming-a-registered-cluster).
- **Node credentials stay out of the process list and of stdout** (#390,
  #395). `lo kubehz node join` gives kubeadm the token in a private config
  file, not as an argument. A join ticket without a script goes to a private
  file. `lo kubehz handover receive` prints the join line of kubeadm without
  the token. `--print-only` and `--print-token` still print the credential.
- **Handover** (#413, #423). `lo kubehz handover preseed` sends the CA keys
  of the cluster over SSH. It now checks the host key of the node on every
  call. The bash implementation did not check it, and the Go implementation
  trusted the first key. A bundle with a link is refused, the key files
  replace their destination and never write through a link, and the
  bootstrap token lives 1 hour, not 24.
- **The kubehz agent CronJob has fewer rights** (#402, #416). It can no longer
  change its own API address, create Secrets in its namespace, or read
  namespaces. Its only write right is `patch`, on one Secret and one ConfigMap.
- **The output of kubectl stays out of the log** (#400, #404, #420, #483).
  The output of an apply or a diff can quote a value of a Secret. lo no
  longer prints it. `LO_SHOW_SENSITIVE_OUTPUT=1` prints it again for most
  applies, see
  [Output that can quote a value](https://lok8s.io/reference/cli#output-that-can-quote-a-value).
  kubectl writes also ignore your kuberc defaults (#420, #485).
- **An error of the Secret plugin no longer quotes a spec value** (#342). It
  names the section and the key.
- **A failed write of the KubeOne manifest leaves no copy in `TMPDIR`**
  (#391, bash implementation). The manifest can hold the registry password.
- **`init`, `add-key` and `remove-key` refuse a private key file** (#489,
  #491, #492) before a tool reads it. A message shows a placeholder for a
  pasted private key, a PEM line or a value with a line break.
- **`lo secrets` refuses an argument that holds a control byte** (#494) before a
  parser can print it. `set` passes, because its value is any text.
- **Plaintext secrets stay out of git** (#463, #468, #469, #470). The
  `.gitignore` of a store is now a block that lo keeps. The plaintext writes
  of `set`, `decrypt` and the Secret generator follow no symlink and no hard
  link. The `.gitignore` of a project also covers the work directories of the
  drivers, which can hold an admin kubeconfig (#392).
- **Kubeconfig writes** (#401, #438, #442, #460).
  `lo kubehz space|cluster kubeconfig --force` follows a link only when no
  other user can redirect it, by owners and mode bits. The write of a hosted
  kubeconfig refuses a directory that another user can write into.
- **Credentials and curl** (#394, #455, #458). A credential with a control
  character is refused before the first request. A curl call with a
  credential reads no user config and writes no TLS key log. A proxy or a CA
  bundle in `~/.curlrc` no longer applies to lo: use `https_proxy` and
  `CURL_CA_BUNDLE`.
- **rook-ceph-csi-kms** grants only the rules of the ceph-csi features that
  you select (#405).
- **Operator image** (#344, #362). It gets its packages over HTTPS, checks
  each download by sha256, and pins each build stage by digest.
- **Pins and dependencies.** mailpit v1.34.0 by digest, with the security
  fixes since v1.30.1 (#493). nginx 1.30.7 by digest for `lo expose` (#484).
  `golang.org/x/crypto` v0.59.0 (#348, #353).

## New

- **`lo secrets remove-key`** (#398, #414, #436) removes an age recipient from
  every creation rule in `.sops.yaml` and re-encrypts the store of the current
  domain (`--all`: each domain store). It makes its checks before the first
  write. It does not revoke what the key already read: rotate those secrets.
- **`LOK8S_SECRETS_NO_MINT=1`** (#487, #490) makes the secrets store read-only
  for one command. lo fails and names the entries of the first Secret that
  would need one. An `update: true` command still runs. Use it for a release
  render or a drift check. See
  [the plugin reference](https://lok8s.io/reference/kustomize-plugins#env-contract).
- **`lo build --keys-only`** (#342) prints the render with each Secret
  emptied: the key names stay, the values go. It reads no store. A ConfigMap
  prints as it is, and a hash of a value that the render holds stays. See
  [the guide](https://lok8s.io/guide/deployment#list-the-keys-of-the-secrets-keys-only).
- **The bootstrap names what a server-side apply drops** (#492). When a
  client-side `kubectl apply` owns fields of a live object, the apply of lo
  removes the ones that the entry does not set, and `kubectl diff` does not
  show that. A dry run and a real run now name the labels and annotations.
  `--skip-client-side-owned` leaves such objects out.
- **`lo doctor`** now also checks:
  - the kind release, v0.18.0 or later (#440, #441);
  - an older `b` (#385), and a bash setup without GNU coreutils (#466);
  - old RBAC objects of system-upgrade-controller, redis-operator (#403) and
    rook-ceph-csi-kms (#426);
  - the Kubernetes range of the system-upgrade-controller kubectl image, also
    in `lo lint` (#457);
  - the SecurityPolicy CRD for sso-gate (#449, #452).
- **kubehz: the `khzb_` bind secret** (#471). lo and the agent accept the new
  form of the bind secret beside the old one.
- **kubehz: the wait after a 503** (#492). A join or a node remove on a hosted
  cluster says what happened and when to run the command again.

## Changes in behaviour

- **Hetzner provision stops on a part without the owner mark.** The parts of
  an existing cluster have none. See
  [Upgrade](https://lok8s.io/releases/v0.15.0#upgrade).
- **Hetzner load balancers send traffic only to servers with the owner mark**
  (#357). `lo provision` removes each other server or selector target, also
  one that an older lo made. A server that lo did not create (for example, a
  machine-controller worker) has no mark. Mark the servers that must stay
  targets before you run `lo provision`.
- **Hetzner descriptors** (#357). A key that is no create flag of its kind is
  refused. A server without `ssh-key` gets no `default-ssh-keys`.
- **`lo recover`** stops before a reimage when you own the `sshPrivateKey` and
  its group or others can access it (#411).
- **`rook-ceph-csi-kms` without `values.kms` stops the render.**
  `kms: [all]` keeps the grants of earlier releases.
- **`lo secrets init` reads the public key**: the `.pub` of `LOK8S_SSH_KEY`,
  by default `~/.ssh/id_ed25519.pub`.
- **A line that starts with `!` in the `.gitignore` of a store is refused**
  below the block of lo, or in a file with no block. A key whose name ends in
  `.enc` is refused too, and `lo secrets set` takes a PEM block on stdin only.
  `lo build` makes the store checks before it writes a value, so a build can
  stop.
- **`lo kubehz handover preseed` refuses an unknown host key.** Add the key to
  your known_hosts file first. `--accept-new-host-key` trusts the first
  contact. The command also stops on an unsafe `/etc/kubernetes/pki` path, and
  it needs GNU coreutils and findutils on the node.
- **`lo kubehz node join`** refuses kubeadm older than 1.22, `--print-only`
  with `--node-ip`, and a `TMPDIR` path with a part that group or others can
  write without the sticky bit (#395).
- **`lo kubehz register` and `deregister` leave a claim key without the label
  of lo alone** (#356), also one that an older lo uploaded.
- **A hosted cluster spec without `spec.kubernetes.version` is refused**
  before the create (#415).
- **`lo expose` fails when a docker step fails.** Before, it printed "cluster
  exposed". Without `.secrets/tls/tls.crt` and `tls.key` it starts no proxy,
  removes the one of an earlier run, and warns (#486).
- **A bootstrap dry run exits 1** when a client-side writer owns fields of an
  object, also without another difference (#492).
- **`lo doctor` exits 1** with a kind older than v0.18.0 when the active
  domain uses the Lo driver, or when there is no active domain (#440, #441).
- **`-o yaml` quotes** each string that a YAML 1.1 reader takes as a bool, a
  null, a number or a time, for example `"off"` (#428).
- **`lo status`** ends after about 5 seconds when the API server does not
  answer, and a call takes at most 12 seconds (#408, #421). It took about two
  minutes. The bash implementation has the 12 second limit only with `timeout`
  on PATH.
- **`lo up` on Docker 28 and later** connects a kind node of an older lok8s to
  the registry network again, so that the default route survives a restart
  (#432).
- **`lo destroy`** names each part that it keeps and exits 0 (#369, #374,
  #375). It refuses a `cluster_name` that a message cannot show (#382).
- **MCP**: the node tools no longer offer flags that their commands always
  refuse (#443, #445).

## Addons and tools

- `fluxcd`: the memory limit of the source, kustomize and helm controllers is
  1Gi, not 256Mi (#490). A Git source of about 60 MB stopped the source
  controller (out of memory).
- `mailpit`: a registry mirror must hold the pinned digest. Else set
  `image.tag` (#493).
- khelm v2.9.0 and helm v3.22.1 (#412).
- `lo toolchain install` pins kind (#366) and, for the bash implementation, yq
  v4.54.3 in a file that it writes. The documented minimum yq of the bash
  implementation is v4.54.3 (#360).
- The operator image ships the flux CLI of the fluxcd addon (#365).

## Upgrade

1. Pin `lo`, the `kustomize-secret` plugin and the `.lok8s` env ref to
   `v0.15.0`, and run `b update`. Also set khelm to `v2.9.0` (and kind
   `v0.32.0` and yq `v4.54.3`, if you use them). `lo toolchain install` prints
   the difference. If you run the operator image, use
   `ghcr.io/kernpilot/lok8s-operator:0.15.0`. If a workflow of yours calls
   `spinup.yml` of lok8s at a tag, set the tag to `v0.15.0`. If you copied one
   of the two workflows, copy it again. Do this before the next steps.
2. **Update the copies in the project.** lo ejects an addon, a driver template
   and the Tilt extension on first use, and a copy in `.lok8s/` wins over the
   files in `lo`. If an env ref syncs `.lok8s/`, `b update` wrote the new
   files. Else run `lo assets diff`, then `lo assets update <rel>` for each
   copy with the state `lo updated`: `bash`, `tilt`, `drivers/lo/cluster`,
   `addons/<name>`. `lo assets update` refuses a copy that you changed: merge
   it by hand. Then apply the bootstrap. In this release, mailpit, fluxcd,
   rook-ceph-csi-kms, the Tilt extension and the `lo expose` proxy config
   changed.
3. **Hetzner provider, one time:** run `lo provision`. It stops before any
   change and prints one `hcloud <kind> add-label` command for each part
   without the mark. Do not run the commands without a check: lo found these
   parts by name only. First make sure with `hcloud <kind> describe <id>` that
   the part is yours. Mark a firewall, placement group, primary IP or snapshot
   image that the descriptor names in the same way. Also mark the servers that
   must stay load balancer targets. Then run `lo provision` again. Until then,
   `lo destroy` does not delete the parts without the mark. See
   [the owner mark](https://lok8s.io/guide/deployment#hetzner-owner-mark).
4. **kubehz agent:** run `lo kubehz deploy` again on each cluster. The agent
   keeps its identity. Until you do, `lo kubehz claim` stops, and the agent
   does not accept a `khzb_` bind secret. Use one lo version for deploy and
   claim: an older lo puts the old agent back. Place a pending claim nonce
   again after the deploy. See
   [An agent that an older lo deployed](https://lok8s.io/guide/kubehz#an-agent-that-an-older-lo-deployed).

   The deploy suspends the CronJob, deletes its Jobs and starts it again. The
   kubeconfig needs `list` and `delete` on Jobs, `list` on Pods and `patch` on
   CronJobs in `kubehz-system`. If the deploy stops, the CronJob can stay
   suspended: run the deploy again. The manifest itself is suspended, so an
   apply without `lo kubehz deploy` stops the heartbeats. A GitOps controller
   must only create `kubehz-agent-state` and the Secret `kubehz-agent`, and not
   reset them.
5. **`rook-ceph-csi-kms`:** add `values: {kms: [...]}` to the entry. To narrow
   the grants, delete the old objects and apply again: the bootstrap does not
   prune. See
   [Change the options](https://lok8s.io/guide/addons#rook-ceph-csi-kms-change-the-options).
   `lo doctor` names the objects that are left over.
6. **Claim key of an older lo:** `lo kubehz register` prints a warning when it
   finds one. If it is yours, delete it in the Hetzner Console (Security, SSH
   keys) and run `lo kubehz register` again.
7. **Secrets store:** the next command that writes the store (`lo secrets`,
   `lo build`) updates its `.gitignore`: commit the change. If a command
   refuses a line of yours, it names the line. Run `lo toolchain install` to
   add the new entries to the `.gitignore` of the project. Ignore rules do not
   change a file that git tracks. Check with `git ls-files`, also for
   `clusters/*/.kubeone/`.
8. Run `lo doctor`.
