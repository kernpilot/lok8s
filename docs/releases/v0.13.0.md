---
title: lok8s v0.13.0
---

This release fixes a Go standard library vulnerability in `lo mcp serve`.
It also ships the changes merged since
[v0.12.0](https://github.com/kernpilot/lok8s/releases/tag/v0.12.0). Read
the Upgrade section before you bump the pins: the envoy-gateway addon
update needs work first.

## Security

- **GO-2026-6859** (CVE-2026-97054, `net/http`). An HTTP/1 server that uses
  `http.MaxBytesReader` can panic when its handler reads the request body
  while it writes the response header. `lo mcp serve` (alias
  `lo mcp stream`) serves the MCP streamable HTTP handler, which wraps each
  request body in `MaxBytesReader`. A request body above its limit (4 MiB by
  default) can make the server panic. The server listens on `127.0.0.1` by
  default. With `--host`, other machines can reach it. `lo` is now built
  with Go 1.26.11, which fixes it (#336). The other `lo` commands use
  `net/http` as a client only.
- **CVE-2026-47775** (Envoy Gateway). The envoy-gateway addon moves from
  v1.9.0 to v1.9.3 (#327). From v1.9.1 on, the default bootstrap encrypts
  OAuth2/OIDC session cookies with AES-256-GCM. An `EnvoyProxy` whose
  `spec.bootstrap` is of type `Replace` (the default when no type is given)
  keeps the old cipher until you set two runtime flags (see Upgrade).
  sso-gate users sign in again once.
- b v4.18.8 sends `GITHUB_TOKEN` only to `github.com` and `api.github.com`
  (#332). `lo toolchain install` does not replace an existing `.bin/b`: run
  `b update b` to get it.
- `github.com/klauspost/compress` v1.20.2, for GO-2026-6865 (#330).
- `golang.org/x/crypto` v0.58.0 (#286, #289) and `google.golang.org/grpc`
  v1.83.2 (#331). The docs site uses `source-map-js` 1.2.2
  (GHSA-68fv-2mgg-jv7q, #321).

## Changes

- The sso-gate addon asks the issuer for `offline_access` (#243). Envoy
  Gateway keeps the refresh token in a cookie for `defaultRefreshTokenTTL`
  (one week by default) and renews the session with it until the issuer
  refuses the refresh token. A sign-out at the issuer does not end that
  session. `docs/guide/addons.md` says how to end one.
- `lo kubehz node cordon`, `uncordon` and `drain` for one node of a Space
  (#334). `lo kubehz status` shows `cordoned` and the last node request
  for each node. The MCP server has the three commands as tools; the drain
  tool is marked destructive.
- The kind node-IP repair also renews the apiserver certificate of a
  control-plane node. Before, the controller-manager and the scheduler
  could not reach the apiserver after the repair. `lo up` then waits for
  the apiserver to be ready. The next `lo up` also repairs a cluster that an
  older version repaired (#328).
- In operator mode, when the agent Deployment of `lo kubehz deploy` does
  not become Ready, the hint names an image pull that fails or hangs
  (#333).
- `lo-install.sh` retries a transient download failure (#329).
- Addons: cilium 1.20.1 to 1.20.4, which starts on kernel 7.2, with
  cilium-envoy v1.37.5 to v1.39.5 (#326);
  envoy-gateway v1.9.0 to v1.9.3 and cert-manager v1.21.1 to v1.21.3
  (#327).
- The toolchain pins b v4.18.8 (#332).
- Docs: current platform facts and fixed anchors (#324); the first run,
  `lo chat`, the MCP guide and the Go driver contract (#325).
- Tests: the bats unit and operator suites and the parity scripts cannot
  fall back to a real cluster through `KUBECONFIG` (#319, #323).

## Upgrade

- **First, update the pins.** Pin `lo`, the `kustomize-secret` plugin and
  the `.lok8s` env ref to `v0.13.0`, then run `b update`. Do this before the
  steps below: `lo assets diff` and `lo assets update` compare against the
  files inside the `lo` you run. From a release older than v0.12.0, follow
  the notes of each release in between first.
- **envoy-gateway v1.9.3: four things before you apply it.** Follow
  "Upgrading to v1.9.3" in `docs/guide/addons.md`:
  1. From v1.9.0 (the version in lok8s v0.12.0): a short TLS outage when
     the new controller starts (about 13 s on one gateway with 2 replicas).
     The addon ships no `EnvoyProxy`. In your own, set `maxSurge: 100%` and
     `maxUnavailable: 0`, keep room for twice the replicas, and apply it
     before the bootstrap. This does not prevent the outage, so plan for
     it.
  2. sso-gate users sign in again once (CVE-2026-47775). An `EnvoyProxy`
     whose `spec.bootstrap` is of type `Replace` (the default when no type
     is given) needs two runtime flags, or it keeps the old cipher.
  3. The default proxy image `distroless-v1.39.5` trusts compromised CAs.
     Set `distroless-v1.39.6` in your own `EnvoyProxy`.
  4. v1.9.3 rejects an OIDC issuer that is not `https://`. Fix each one
     first.
- **sso-gate: check your issuer.** The client needs the refresh-token
  grant. The issuer must accept `offline_access`: a strict issuer that
  refuses the scope breaks the sign-in, while the policy still shows
  `Accepted`. To keep the old scopes, apply the removal patch from the
  header of `.lok8s/addons/sso-gate/kustomization.yaml`
  (`docs/guide/addons.md` explains it).
- **Bring the new addon files into the project.** cilium, envoy-gateway,
  cert-manager and sso-gate changed. If an env ref syncs `.lok8s/`,
  `b update` writes the new files into `.lok8s/addons/<name>/`. Before it
  overwrites a file you changed, b asks (the default `safety: prompt`).
  Without a terminal it refuses, unless you pass `--yes` or set
  `safety: auto`. `b update --strategy=merge` keeps your changes with a
  three-way merge. If no env ref syncs `.lok8s/`, `lo` ejects an addon on
  first use and never overwrites it. Run `lo assets diff addons/<name>` to
  see the changes, and `lo assets update addons/<name>` for an untouched
  copy. Merge a changed copy by hand. Then apply the bootstrap.
- **`lo mcp serve --host`.** If you bind it to an address other than
  loopback, upgrade now, or bind it to a loopback address until you can.
- To build `lo` from source, you need Go 1.26.11 or later (`go.mod`).
