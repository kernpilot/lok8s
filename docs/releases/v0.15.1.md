---
title: lok8s v0.15.1
---

This release fixes `lo provision` for a cluster that kubehz hosts: a second
run no longer creates a second cluster for the same domain. It also installs
kubehz-agent v0.2.0 and updates three addons. It ships the changes merged
since [v0.15.0](https://github.com/kernpilot/lok8s/releases/tag/v0.15.0).

**Some kubehz commands now stop where v0.15.0 went on.** Read
[Changes in behaviour](https://lok8s.io/releases/v0.15.1#changes-in-behaviour)
first if your account has more than one cluster for a domain.

## Fixes

- **A hosted `lo provision` creates one cluster for one domain** (#503).
  Before, each run with `spec.kubehz.hosting: hosted` sent a new create, and
  kubehz made one more cluster each time. Now lo reads your cluster list
  before the create. If the list has one hosted cluster for
  `spec.cluster.domain` that is ready, lo downloads its kubeconfig and sends
  no create. Any other cluster of the domain stops the run, and lo names the
  clusters. If a create gets no answer, lo reads the list again and names
  what it shows. kubehz checks such a create, and usually keeps or removes
  the cluster in about 3 minutes. When the check fails, kubehz tries again
  about 15 minutes later. Do not run `lo provision` again before kubehz keeps
  or removes the cluster. Then run it again: lo downloads the kubeconfig of a
  kept cluster, or creates a new one.
- **`lo provision` also uses a Paused or Updating cluster, and a refused
  kubeconfig download names its cause** (#504). For a Paused or Updating
  cluster of the domain, lo downloads the kubeconfig. For each other status,
  it gives one next step. A refused download names the cause (no answer, or
  the HTTP status and the code of the api) and, for three codes, the next
  step. `lo status` reads the live status of a hosted cluster.
- **The `spinup.yml` summary** tells you to claim the cluster with the claim
  code of the agent (`lo kubehz deploy`, then `lo kubehz claim-code`, then the
  One-time code tab), not with the ticket of the run (#501). A registration
  that you claim with that ticket gets no heartbeat.

## Changes in behaviour

- A hosted `lo provision` stops when the domain already has a cluster that
  lo cannot use, or more than one cluster (#503, #504). It also stops when lo
  cannot read the cluster list, or when the list holds only a part of your
  clusters. In each case, lo creates no cluster.
- `lo kubehz deregister` and `lo destroy` of a hosted cluster delete nothing
  when your account has more than one cluster for the domain (#504). Before,
  they deleted the oldest one. lo names the clusters: remove the one you mean
  in the dashboard.
- `lo kubehz node join`, `node remove` and `node status` stop when the domain
  has more than one cluster (#504). lo names the clusters, and
  `--cluster-id` selects one.
- `lo kubehz assess` and `lo kubehz re-enroll` warn when the domain has more
  than one cluster (#504). They name the clusters and use the oldest one, as
  the server does when it binds the agent.
- The lookup of the cluster of a domain stops when the cluster list holds
  only a part of your clusters, or when the id of the cluster does not have
  the `cl-` shape (#504). `lo status` then prints `unknown`, not
  `not registered`.
- A kubeconfig download takes only a 2xx answer (#504). A 3xx answer is no
  kubeconfig.

## The kubehz agent and the addons

- **kubehz-agent v0.2.0** (#502). `lo kubehz deploy` installs the v0.2.0
  image. At `access: managed`, the grants are narrower: the agent lists and
  patches MachineDeployments and lists and deletes Machines, and it no longer
  has `get` and `watch` on them. A new Role in `kubehz-system` lets it create
  the Lease `kubehz-live-agent`, and get and update it. The agent acts only
  while it holds the Lease, so more than one replica is safe at that tier.
- **Addons** (#497): `fluxcd` chart 2.19.1 (Flux 2.9.5), `monitoring`
  (kube-prometheus-stack 88.6.5) and `reflector` 10.0.81. The operator image
  ships the flux CLI 2.9.5.

## Docs

- **The kubehz guide and the README** (#496). The guide says what is
  available today: a Space has no ingress, no certificates, no persistent
  volumes and no LoadBalancer or NodePort for your apps, and an eject cannot
  start yet. The README is shorter.
- **The kubehz guide follows the platform as it runs now** (#499): the
  preview rules of Spaces, the launch trial and the billing start, what the
  live agent can do, agent keys and the sign-up cap. The help of
  `lo kubehz handover` says that kubehz cannot start an eject yet.

## For contributors

- CI scans the Go and docs dependencies each day, offline (#498).
- CI uses golangci-lint v2.15.0, which reads the export data of Go 1.27 (#500).
- The kubehz api stub of the parity harness has no Space with its own control
  plane, because the api no longer has one (#505).

## Upgrade

1. Pin `lo`, the `kustomize-secret` plugin and the `.lok8s` env ref to
   `v0.15.1`, and run `b update`. If you run the operator image, use
   `ghcr.io/kernpilot/lok8s-operator:0.15.1`. If a workflow of yours calls
   `spinup.yml` of lok8s at a tag, set the tag to `v0.15.1`. If you copied
   `spinup.yml`, copy it again.
2. **Update the copies in the project.** If an env ref syncs `.lok8s/`,
   `b update` wrote the new files. Else run `lo assets diff`, then
   `lo assets update <rel>` for each copy with the state `lo updated`. In this
   release, `bash`, `addons/fluxcd`, `addons/monitoring` and
   `addons/reflector` changed. Then apply the bootstrap, so that the three
   addons get their new charts. For fluxcd on a running cluster, read step 3
   first.
3. **fluxcd on a running cluster:** the chart's one-shot Job
   `flux2-flux-check` in `flux-system` stops the apply of the addon, because
   its image changes and the template of a Job cannot change. Delete that
   completed Job, then apply again.
4. **kubehz live agent:** run `lo kubehz deploy` again on each cluster that
   runs it, at every `access` level. The deploy applies the v0.2.0 image. At
   `access: managed`, it also applies the Lease Role and its binding, so the
   new agent can act.
