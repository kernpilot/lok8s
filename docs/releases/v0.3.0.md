# lok8s v0.3.0

`lo` is one Go binary. Every command runs natively in it. The frozen argsh
tree is embedded in the binary and stays runnable: a project selects it per
command through `lok8s.yaml` (`spec.implementation`).

## Install

New installs use `lo-install.sh`. Download it and `checksums.txt` from the
release, verify, read, then run it. See [Installation](/guide/#installation).

Two builds, both installed as `lo`:

- `lo` (core, about 18 MB): renders through the pinned `kustomize` binary and
  the exec plugins that `lo toolchain install` installs with `b`.
- `lo-full` (`lo-install.sh --full`): links the kustomize API and khelm and
  renders in-process. Both builds render byte-identical output.

## New

- `lo init`: on a terminal, a wizard. It detects where you stand, asks,
  prints the plan, then writes. `lo init --plan` prints the plan and writes
  nothing. Every answer has a flag twin on a subcommand.
- `lo toolchain install` and `lo toolchain doctor`: write `.bin/b.yaml` with
  the pins this `lo` was built against, install `b` (SHA-256 verified) and
  run `b install`.
- `lo assets`: the eject model. The addons, the driver templates, the CRD
  mirror, the Tilt extension and the bash tree ship inside the binary and
  land in `.lok8s/` on first use. `lo assets list|diff|eject|update` manage
  the copies; a local copy always wins.
- `lo mcp`: the MCP server for editors and agents, from the same binary.
- `lo secrets` uses the kernpilot age-only sops fork. The cloud KMS, Vault
  and PGP backends are out; a rule with such a recipient is rejected.

## Removed

- `LO_IMPL` and `LO_GO_BASH`. Nothing in the environment selects the
  implementation; `lok8s.yaml` does.
- `lo assets show`. Use `lo assets diff <rel>`.
- `lo init project --env both`. Pick `mise`, `direnv` or `none`.

## Deprecated

- `lo init toolchain`: a hidden alias of `lo toolchain install`, kept for
  this release only.

## Breaking

- `.lok8s/lo` no longer marks a project root. The binary walks up to the
  nearest `clusters/` directory or a `kind: Project` `lok8s.yaml` (D30).
- Install through `lo-install.sh` or the release archives. `lo-up` stays
  served as legacy and does not install the Go binary. `go install
  github.com/kernpilot/lok8s/cmd/lo@v0.3.0` is unsupported: the module
  carries `replace` directives.

## Upgrade an existing project

1. Install the binary: `bash lo-install.sh`.
2. Add `lok8s.yaml` at the project root if there is none:

   ```yaml
   kind: Project
   spec:
     implementation:
       default: go
   ```

3. Run `lo toolchain install`. It never overwrites an existing `.bin/b.yaml`;
   it prints a diff against the pins.
4. Optional: `lo assets eject bash` writes the frozen tree into `.lok8s/`,
   so `spec.implementation.bash.commands` can route a command to it.
5. Run `lo doctor`.
